# Behavior School Book Engine

## Reading experience

A book page is intentionally more than a summary:

1. **Identity** — title, author, edition, category, poster
2. **Core thesis** — the book in plain English
3. **Learning lab** — mechanism + neuroscience lens
4. **Visual model** — SVG + Mermaid
5. **Concrete story** — make abstraction memorable
6. **Examples** — translate into daily life
7. **Pattern detector** — avoid false recognition and overgeneralization
8. **Field experiment** — active practice
9. **Mental models** — compact retrieval units
10. **Action protocol** — convert insight into behavior
11. **Deep dive** — long-form explanation
12. **Retrieval** — quiz/poll where available
13. **Related reading** — internal discovery

## Memory-friendly writing
Prefer:
- concrete before abstract
- examples before definitions when the idea is unfamiliar
- chunking
- contrast
- repetition with variation
- prediction → explanation
- active recall
- small experiments
- visual summaries

## Neuroscience policy
Neuroscience is an explanatory lens, not a magic credibility layer.
Do not:
- map every idea to a single brain region
- claim a neurotransmitter directly explains a complex behavior
- present weak correlations as causal facts
- imply that imaging findings prove individual diagnosis

## Visual system

Each book can have:
- static SVG poster
- inline flowchart SVG
- Mermaid concept map
- visual artifact
- comparison cards
- process loop

The best visual is the simplest representation that makes an invisible mechanism visible.

## Content length target for automated books
The hourly pipeline should produce a genuinely substantial reading experience:
- summary: 150–300 words
- deep dive: 1,500+ words
- key takeaways: 5–8
- protocols: 4–7
- examples: 3–6
- pattern warnings: 3–6
- practice: 4–6

Longer is acceptable when it adds distinct value.
